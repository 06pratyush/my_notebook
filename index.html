The Phases of Machine Learning

№ 10 · machine learning · ML pipeline · from ML Fundamentals

Every machine learning project follows the same skeleton: a dataset is split, a model is built, and its worth is judged. The pipeline has three phases — Train, Test, and Evaluate — and the order is not negotiable.

A dataset arrives and is carved into three slices: Train, Test, and Validate. The training set feeds the model development — the algorithm learns its patterns there. The test set is held back entirely; once the model is built, it faces the test set cold, and predictions are made on data it has never seen. Finally, the evaluation phase judges the model's performance: how far the predictions stray from reality, and whether the model has truly learned the structure or merely memorised the noise.

The standard split is 70% Train, 30% Test — though the exact proportions shift with the size of the dataset. What matters is the principle: the model must never peek at the test data during training, or the evaluation is a lie. This pipeline stands in quiet parallel to the second law of thermodynamics: just as entropy demands a direction, the ML pipeline demands a sequence — train first, test after, evaluate last. The types of learning determine what happens inside each phase.

Types of Machine Learning

№ 11 · machine learning · taxonomy · from ML Fundamentals

Machine learning splits into three great families, and the difference between them is simply what the data carries with it when it arrives.

Supervised learning — the data is labelled. Each input comes paired with the correct answer, and the model's job is to learn the mapping from one to the other. Classification (is this email spam?) and regression (what will this house sell for?) both live here. The teacher has already marked the answers; the model merely studies them.

Unsupervised learning — the data is unlabelled. No answers arrive; only inputs. The central focus becomes similarity: which data points cluster together, which variables move in lockstep, which structures hide beneath the surface. K-means, PCA, and hierarchical clustering are its tools. The model must find order without being told what order looks like.

Reinforcement learning — an agent acts in an environment and receives rewards or penalties. There is no fixed dataset at all; instead, the agent learns by doing, maximising cumulative reward over time. Game-playing AIs, robotics, and recommendation engines that adapt to user behaviour all belong here. It is the most animal of the three: trial, error, and the slow shaping of behaviour by consequence.

Linear Regression & Its Assumptions

№ 12 · machine learning · regression · from ML Fundamentals

The goal of linear regression is deceptively simple: find the straight line that best fits the data — the line that minimises the sum of squared errors between what the model predicts and what actually happened. The equation is y = mx + c, generated from historical data where x is the input and y is the output.

Consider a small dataset: when x = 0, y = 0; x = 1, y = 2; x = 2, y = 5; x = 3, y = 9; x = 4, y = 15; x = 5, y = 21. The predicted values ŷ might be 0, 6, 9, 13, 16, 20 — giving errors of 0, −4, −4, −4, −1, +1. The line does not pass through every point; it finds the compromise that loses the least across all of them. But before applying any model, one must perform EDA — exploratory data analysis — to understand the data's shape before demanding it fit a line.

The method rests on five assumptions, and if any one of them is violated, the model's conclusions become unreliable:

→ Linearity — the relationship between x and y must be linear. Either x ∝ y or y ∝ x; the data must trend in a straight line, not a curve.

→ Homoscedasticity — the error term must have constant variance. The residuals should not follow any trend; they must be near-constant in spread, neither fanning out nor narrowing as x increases. (The note on residual analysis explores this visually.)

→ Independence — error terms should be independent of each other. No residual should influence another; the errors must not be correlated across observations.

→ Normality — error terms should be normally distributed, with the mean of residuals approximately zero. The bell curve of errors should centre on the line.

→ No multicollinearity — independent variables should have no relation to each other. No redundant variables; each predictor must stand on its own. This connects to the Pearson correlation coefficient, which measures exactly such relationships.

Residual Analysis

№ 13 · machine learning · diagnostics · from ML Fundamentals

A residual is the gap between what the model predicted and what actually happened — the error for a single observation. Plot every residual against the input variable x, and the resulting scatter plot tells you whether the assumptions of linear regression hold or have been violated.

Two shapes matter most. In a homoscedastic plot, the residuals scatter uniformly across the graph — a flat band of noise with no pattern, the error does not change with change in x. This is what you want: the model's mistakes are evenly distributed, and the assumption of constant variance is satisfied.

In a heteroscedastic plot, the residuals fan out — the error changes with change in x, growing wider (or narrower) as x increases. The spread of residuals is not constant; the model is more confident in some regions and less in others. When this pattern appears, the standard errors are wrong, confidence intervals are unreliable, and the model needs attention — perhaps a transformation of the variables, or a different model entirely.

Performance Metrics

№ 14 · machine learning · evaluation · from ML Fundamentals

How do you judge a model's worth? Not by how well it fits the training data — any model can memorise — but by how honestly it captures the underlying structure. Seven metrics form the standard toolkit, each revealing a different facet of the model's performance.

1) R² (Coefficient of Determination) — lies between 0 and 1. Equals 1 − Σ(y − ŷ)² / Σ(y − ȳ)², where y is the actual output, ŷ is the predicted output, and ȳ is the mean of actuals. Closer to 1 means less error, better prediction. Closer to 0 means the model explains almost none of the variance. This is also called the goodness of fit — the fraction of the total variation that the model accounts for.

2) Adjusted R² — equals 1 − (R² − 1)(n − 1) / (n − k − 1), where k is the number of input dimensions, variables, or attributes, and n is the number of observations. Unlike plain R², it penalises the model for adding useless variables. A model with ten predictors and the same R² as one with two is not actually better — the adjusted R² knows this.

3) Mean Squared Error (MSE) — Σ(y − ŷ)² / N. The average of the squared differences. Squaring punishes large errors more than small ones; a single wild prediction inflates the MSE disproportionately.

4) Root Mean Squared Error (RMSE) — √MSE. Brings the error back into the original units of y, making it interpretable: "the typical prediction is off by this many units."

5) Mean Absolute Error (MAE) — Σ|y − ŷ| / N. The average of the absolute differences. More robust to outliers than MSE because it does not square the errors; every mistake counts equally.

6) Mean Absolute Percentage Error (MAPE) — MAE × 100, expressed as a percentage. Useful for comparing models across datasets with different scales: "the model's predictions are off by X% on average."

7) Pearson Correlation Coefficient (r) — measures how two variables are correlated. Equals Σ(xᵢ − x̄)(yᵢ − ȳ) / √[Σ(xᵢ − x̄)² × Σ(yᵢ − ȳ)²]. Ranges from −1 (perfect negative correlation) through 0 (no correlation) to +1 (perfect positive correlation). It does not measure causation — only the strength and direction of the linear relationship between two variables. (The note on multicollinearity uses this to detect redundant predictors.)
