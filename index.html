The Phases of Machine Learning

№ 1 · machine learning · ML pipeline

Every machine learning project follows the same skeleton: a dataset is split, a model is built, and its worth is judged. The pipeline has three phases — Train, Test, and Evaluate — and the order is not negotiable.

A dataset arrives and is carved into three slices: Train, Test, and Validate. The training set feeds the model development — the algorithm learns its patterns there. The test set is held back entirely; once the model is built, it faces the test set cold, and predictions are made on data it has never seen. Finally, the evaluation phase judges the model's performance: how far the predictions stray from reality, and whether the model has truly learned the structure or merely memorised the noise.

The standard split is 70% Train, 30% Test — though the exact proportions shift with the size of the dataset. What matters is the principle: the model must never peek at the test data during training, or the evaluation is a lie. Train first, test after, evaluate last. The types of learning in Types of Machine Learning determine what happens inside each phase.

Types of Machine Learning

№ 2 · machine learning · taxonomy

Machine learning splits into three great families, and the difference between them is simply what the data carries with it when it arrives.

Supervised learning — the data is labelled. Each input comes paired with the correct answer, and the model's job is to learn the mapping from one to the other. Classification and regression both live here. The teacher has already marked the answers; the model merely studies them.

Unsupervised learning — the data is unlabelled. No answers arrive; only inputs. The central focus becomes similarity: which data points cluster together, which variables move in lockstep, which structures hide beneath the surface. K-means, PCA, and hierarchical clustering are its tools.

Reinforcement learning — an agent acts in an environment and receives rewards or penalties. There is no fixed dataset at all; instead, the agent learns by doing, maximising cumulative reward over time. Game-playing AIs, robotics, and adaptive recommendation engines all belong here.

Linear Regression & Its Assumptions

№ 3 · machine learning · regression

The goal of linear regression is deceptively simple: find the straight line that best fits the data — the line that minimises the sum of squared errors between what the model predicts and what actually happened. The equation is $y = mx + c$, generated from historical data.

Consider a small dataset: when x = 0, y = 0; x = 1, y = 2; x = 2, y = 5; x = 3, y = 9; x = 4, y = 15; x = 5, y = 21. The predicted values $\hat{y}$ might be 0, 6, 9, 13, 16, 20 — giving errors of 0, −4, −4, −4, −1, +1. The line does not pass through every point; it finds the compromise that loses the least. But before applying any model, one must perform EDA — exploratory data analysis.

The method rests on five assumptions:

→ Linearity — the relationship between x and y must be linear.

→ Homoscedasticity — the error term must have constant variance. (The note on residual analysis explores this visually.)

→ Independence — error terms should be independent of each other.

→ Normality — error terms should be normally distributed, with mean of residuals ≈ 0.

→ No multicollinearity — independent variables should have no relation to each other. No redundant variables.

Residual Analysis

№ 4 · machine learning · diagnostics

A residual is the gap between what the model predicted and what actually happened — the error for a single observation. Plot every residual against the input variable x, and the resulting scatter plot tells you whether the assumptions of linear regression hold or have been violated.

In a homoscedastic plot, the residuals scatter uniformly — a flat band of noise with no pattern, the error does not change with change in x. This is what you want: the model's mistakes are evenly distributed.

In a heteroscedastic plot, the residuals fan out — the error changes with change in x, growing wider (or narrower) as x increases. The spread is not constant; the model is more confident in some regions and less in others. When this pattern appears, the standard errors are wrong and the model needs attention.

Performance Metrics

№ 5 · machine learning · evaluation

How do you judge a model's worth? Not by how well it fits the training data — any model can memorise — but by how honestly it captures the underlying structure.

1) R² (Coefficient of Determination) — lies between 0 and 1. Equals 1 − Σ(y − $\hat{y}$)² / Σ(y − $\bar{y}$)². Closer to 1 means less error, better prediction. Also called the goodness of fit.

2) Adjusted R² — equals $R^2_{adj} = 1 - \frac{(R^2 - 1)(n - 1)}{n - k - 1}$, where k is the number of input dimensions. Penalises the model for adding useless variables.

3) Mean Squared Error (MSE) — Σ(y − $\hat{y}$)² / N. Squaring punishes large errors more than small ones.

4) Root Mean Squared Error (RMSE) — $\text{RMSE} = \sqrt{\text{MSE}}$. Brings the error back into the original units of y.

5) Mean Absolute Error (MAE) — Σ|y − $\hat{y}$| / N. More robust to outliers than MSE.

6) Mean Absolute Percentage Error (MAPE) — MAE × 100, expressed as a percentage.

7) Pearson Correlation Coefficient (r) — measures how two variables are correlated. Equals Σ(xᵢ − $\bar{x}$)(yᵢ − $\bar{y}$) / √[Σ(xᵢ − $\bar{x}$)² × Σ(yᵢ − $\bar{y}$)²]. Ranges from −1 to +1.
